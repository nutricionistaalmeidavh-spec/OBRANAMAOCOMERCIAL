# NF-e P1 — deterministic recognition and operational integration

- No AI, embeddings, cloud inference or paid API. Saxes 5.0.1 (ISC) and xmlchars 2.2.0 (MIT) are pinned and bundled. No runtime npm install.
- Read original XML bytes in the renderer for display and again on the authoritative Desktop or LAN backend. The authorization protocol is a claim in the XML, not a cryptographic signature or live SEFAZ validation.
- Match confirmed company/supplier/product/unit identities; GTIN, references, technical attributes and token similarity suggest candidates. Explicit human confirmation is required for a new equivalence; conflicting attributes are not auto-approved.
- Purchase CFOP allowlist is conservative. Returns, remittances, mixed or unrecognized CFOP and non-production NF-e cannot enter the purchase integration flow. Documentary entry remains available.
- Wizard includes multiple works/stages/substages, original fiscal quantities and exact rational stock conversion, physical receipts (zero by default), installments and existing purchase/receipt/account reconciliation. Only explicit confirmation runs the atomic domain operation.
- Archive original XML, key and hash; fiscal data immutable, ledger canonical, idempotency and rollback. Reuse earlier receipt/account only on explicit selection; no silent duplicate. Follow-up receipts update linked order and canonical stock together. Compensating reversal of newly created receipts/payables preserves history; prior linked receipts/accounts and paid accounts require manual financial reconciliation before reversal, not automatic destruction.
- Work appropriation is a read-only projection of the original payable, not a second obligation. Each installment is distributed over remaining destination costs with integer cumulative allocation and last-cent reconciliation. Partial payments and bank allocations use deterministic FIFO by ordered cost-center allocation IDs; all allocated cents reconcile to the single original payment. This FIFO policy is an explicit design choice, not a fiscal rule.
- DRE, local work overview, mobile summary and bank cash forecast use apportioned views; company cash flow uses canonical obligations. PWA individual payable sync retains canonical IDs and has not been extended to publish split obligations. Bank audit transaction-level rows still show original transactions rather than synthetic split bank transactions.
- Finance migration maps all fiscal links and base64 original XML bytes with SHA-256 verification. Older server capability is required to migrate integrated notes; no partial migration or local fallback. Estornadas retained in fiscal migration export.
- Remaining release gates: final CI on head, browser/Electron full UI walkthrough with synthetic XML, real installer upgrade/backup and profiler. No merge/release without explicit authorization.
